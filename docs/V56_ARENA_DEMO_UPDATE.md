# Arena 5.6 시연 보완

기준은 `17e3bf5b`에서 수행한 12건 합성 비교와 A/B/C 실행 기록이다. Arena의 의미 정책을 `v54-semantic/2`로 갱신했다. 모델 가중치, 질문 11개, 0.70 임계값은 동일하다.

| 관찰 | 보완 | 검증 결과 |
| --- | --- | --- |
| 인증번호 금지문이 모호한 요청 업무를 생성 | 전체 문장이 인증정보 전달 금지 형태이고 조로의 발화·노출·지급 답변이 뒷받침하는 경우만 현재 강한 요구 미감지 | M02 새 업무 0건. 직접 요청 M01 및 경고 뒤 실제 요구 M10 모두 중단 |
| 과거 인용에 새 확인 업무가 생김 | 과거 시점과 닫힌 인용·전달 문장이 확인되는 제한된 경우 주의 안내 | M03 주의 안내, 새 업무 0건. 인용 밖에 또 다른 지시가 있으면 새 규칙에서 제외 |
| 연결 복구 뒤 재시도 업무가 남음 | 유효한 응답이 저장되면 같은 세션·입력의 기술 재시도 업무를 `MODEL_RETRY_RESOLVED`로 기록 | 기존 중단·확인 업무 및 이전 위험 유지. 기존 요청 ID 재시도에서 추가 모델 호출 0회 |
| 화면에서 실패와 이전 위험 보류를 구분하기 어려움 | 연결 실패와 복구 안내를 분리하고, 생성 모델 비교 카드를 제거 | 업무 큐에 집중. 연구용 서버 API는 별도 사용 가능 |

같은 12건의 합성 문장과 사전 기대에 대해 실제 조로로 재평가해 **10/12 → 12/12**가 일치했다. 계좌 변경 요청의 우선 표시·복수 업무 보존·보관 후 재개와 로컬 연결 단절 후 복구를 포함해 이번 테스트에서 실제 응답 17건을 받았다. 이 수치는 수정에 사용한 사례의 재검증이며 독립 성능 평가는 아니다. 실행은 Zoro-1 `bf1b76b9`, RTX 5080, 서버 적용 온도 **1.59**로 수행했다. 계약의 **1.52**는 이전 기준값이며 화면에서 별도로 설명한다.

시연은 **모호한 기존 업무 → 별도의 계좌 변경·송금 확인 업무가 맨 위로 올라옴 → 보관 후 재개** 순서가 적합하다. 첫 도입 가설은 메신저 기반 지급 요청을 처리하는 소규모 회계팀이다. 수동 확인 대비 미처리·인계 누락·확인 완료 시간을 파일럿에서 비교한다. 은행 인증, 거래 차단, 외부 발송 및 조직 간 실인계는 제품 검증 범위 밖이다. `noul`과 `choice`의 실제 판단 근거를 보여주고 `score`는 기술 기록의 참고값으로 남긴다.
