## 적용 순서 (심사 직전 변경관리)

1. **P0 — 비판단/비권한 작업**: 현재 룰북 결함 문서 보관·검수, 반례 재현 계약 테스트, 현재 핵심 모델 경로 불변 확인. 기존 정책에 자동으로 새로운 룰북을 붙이거나 무료 Jev 호출하는 일 없음.
2. **P1 — 가역적 정적 감사 후보**: 별도 audit CLI에서 규칙 충돌/동치와 미포함 질문, 정보소실 경로를 진단하되 운영 중 `decide()` 실행 결과는 변경하지 않음.
3. **P2 — 변경 가능성 있는 수정**: RB-1 정규화 확장, RB-2 질문별 불확실성, RB-3 안전 hit policy, ZP-1 금액/어휘 정규화는 **동일 입력 결과 비교표와 독립 잠금평가를 확보한 별도 PR**로만 반영.
4. **P3 — 모델**: 데이터 권리·독립 인간 라벨·잠금셋/보정셋 분리·실제 Zoro 체크포인트/decision-head 로그 확보 후 질문 변경·fine-tuning을 검토. 소스 추가나 Markdown 업로드는 학습이 아니다.

## 사용자 UX와 신뢰 경계

일반 이용자는 검토할 합성·비식별 텍스트를 붙여넣고, 판단 결과와 상황별 후속 안내만 확인한다. 내부 사례 프리셋, OPEN Task 편집, Jev 유료 실험 패널 및 룰북 로드 결과는 일반 화면에서 숨긴다. 이것은 **AI가 자동으로 사기 여부를 완벽하게 판별한다는 의미가 아니다**. 기존 Zoro 판단/독립 정책은 유지하며, 미해결 위험/사람 확인 필요는 일반 결과에 간결하게 계속 표시한다. Jev는 기본 비활성, 사용 동의 없는 네트워크/과금 금지.

판단 진행 표시도 실제 `/api/evaluate` 요청/서버 응답 이벤트에만 연결한다. 스트리밍되지 않는 서버 내부 단계를 가상의 퍼센트나 임의 지연으로 재연하지 않는다.

## SNM · 4D · 복구

- **SNM**: 직접 송금 명령, 과거 인용·예방 경고, 애매한 링크, 모델 오류, 지연/중복 응답, 사용자 개인정보 붙여넣기, 상태 변경, 잘못된 룰 우선순위, 외부 Jev 비인가, 리로드를 별도 케이스로 다룸.
- **4D 구조**: 입력 → 모델 제안 → 계약 → 독립 정책 → 세션/업무 이력 → 읽기 전용 후속 규칙.
- **시간**: 판단 요청/서버 응답/저장 확정과 UI 상태를 구별; 현재/과거 위험 구분.
- **관점**: 사용자 간결함과 운영자/심사위원의 재현 가능성을 함께 확보하되 출처·한계는 숨기지 않음.
- **역검증**: 사용자 결과에서 정책·모델 출처·세션 버전으로, 문서 지적에서 소스 경로/반례로 추적.

**롤백:** UI 관련 PR만 revert. 룰북/ v51 정책/모델/DB가 바뀌지 않았으므로 해당 마이그레이션 없음. 누적 원본 장부 기록은 삭제·덮어쓰지 않음.
