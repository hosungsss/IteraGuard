# 의심계 v4.8 · 사업/금융/가상자산 위험 근거 검토 및 Zoro 진단 계약

## 사용자 기능과 명확한 범위

- **현재 실제 구현:** `앱 > 확장 검증 > 사업·투자 위험 근거 검토`에서 네트워크마케팅·블록체인·투자·온라인 플랫폼 문구를 **오프라인 패턴 기반으로** 분석한다. 근거 문자열과 위치를 추출하고 검증 질문을 분류한다. 모델 추론도, 등록/계좌/블록체인 API 조회도 수행하지 않는다.
- **기존 보존:** 온디바이스 KoELECTRA 판단, LinkGuard URL 사전 검사, 기기 안의 APK 정적 검사, PAYLOCK, 기존 `dmsg` 4개 정책 상태. 추가 기능은 기본 판단을 승격/하향하지 않는 **별도 예비 실사 패널**이다.
- **존재하지 않는 기능:** 실시간 재무제표 분석, 온체인 스마트컨트랙트 감사, 브라우저 뒤의 서버 코드 분석, 사업 등록 실시간 검색, 사기 범죄 판정, 수익률·불법성 확률 추정, NPU/실제 Zoro-1 추론 재검증.

텍스트 정규식은 표현의 관찰만을 의미한다. 법률상 자격·허가, 영업·금융 피해, 사기범죄의 구성요건을 검증하지 않는다. 경고/인용 문맥의 유사 표현은 `QUOTED_OR_WARNED`로 별도 표기하며 실제 의도는 검증되지 않았다고 표시한다.

## 업데이트 파일에서 채택한 중요한 원칙

2026-11-02자 `update files.zip`의 4개 자료를 원본 해시와 함께 보관한다. 보고서는 v4.5 기준의 분석 결과이지 v4.8 실측 결과가 아니다.

1. **모델의 최고 후보와 정책의 최종 안내를 분리:** report 3은 보관된 72건의 모델 응답과 총 73건 판정을 재생한 결과를 기술한다. 25건의 기존 평가에서 최종 기대 안내 일치 7/25·보류 19/25라는 보고가 있다. 내부 보고의 주장으로 취급하며 이번 환경에서 원시 추론 파일을 재검증하지 않았다.
2. **한 가지 reason code로 전체 보류 원인을 대표하지 않음:** `tools/zoro/trace_v48.py`는 기존 승인된 Zoro 응답을 입력받으면 행동·화행 confidence, 충돌, 선택 근거 부족을 병렬로 기록한다. 원문 자체는 출력 파일에 저장하지 않는다. 실행하지 않은 원본 Zoro 실험을 재실행했다고 주장하지 않는다.
3. **질문 범위 정합성:** 일반적 방문 안내 요청 `direct_request`와 지원 위험 행동 `none`은 논리적으로 동시 발생 가능하다. 이를 자동으로 위험 없음으로 완화하지 않고, 질문 명세·합성 반례·새 독립 검증이 완료된 경우에만 정책 변경한다.
4. **근거 충분성과 요청 부재의 구별:** 정보 서술이면 `q_evidence=no`가 나올 수 있다는 보고 3의 문제를 기록했다. 다만 기존 위험 경계를 임의로 해제하지 않는다.
5. **기존 중간 계층 유지:** 보고서 4는 모델과 정책 사이의 어댑터가 이미 있으므로 추가 프록시 서버 신설을 필수로 보지 않는다. v4.8에서도 별도 서버와 유료 API를 추가하지 않는다.
6. **확률/임계값 미변경:** 0.70은 도메인 검증된 정책 기준이 아니다. 모델을 탓해 일괄 하향하거나 공식 모델 temperature 값을 임의 복사하지 않는다. 필요시 개발·보정·독립 잠금 세트에서만 수정할 수 있다.
7. **Reason-then-Decide는 조건부 실험:** 실제 Zoro 체크포인트/서버가 있을 경우 직접판정과 추가 추론을 비교한다. 이 릴리스에 실제 Zoro inference 지표를 새로 생성하지 않았다.

## 평가·반례·회귀

`node tools/test_domain_v48.js`로 기초 13개 패밀리 테스트를 실행한다. 초기 작성·고정된 합성 예시로, 실세계 사기 탐지율이나 독립 정답률이 아니다. 사기예방 인용·합법적 추천보상·개인키 요구·출금 선납·월 구매 자격·계약자 권한·일반 안내를 분리한다. 모든 결과는 텍스트만으로 제기할 수 있는 **추가 확인 과제**에 한정된다.

향후 독립 평가는 실제 국가와 관할법, 공개 출처·원본 증빙·적법한 데이터 사용, 비교 기준선, 오탐/미탐, 상담원 판단 불일치 등을 분리한다. `model_score ≠ P(fraud)` 원칙을 유지한다.

## SNM / 4D / NPU

- **SNM:** 보상 구조가 합법적으로 운영되는 경우, 사업 자체는 합법이지만 참여자가 허위 수입을 주장하는 경우, 온체인 코드는 정상이나 웹사이트가 가짜인 경우, 거래소 로그인과 API 키 요구가 다른 경우, 정상 광고를 비난하는 인용문 등 반례를 포함한다.
- **4D:** 판매자/구매자/모집자/플랫폼/체인/토큰/컨트랙트/모델/사람의 주장과 외부 검증 사실을 분리한다. 제안일, 등록일, 실제 거래·출금 시점, 검증한 블록 높이 등 시간의 유효범위를 별도로 기록한다.
- **NPU:** 기존 기기 내부 NLP는 유지한다. 새 예비 실사 모듈은 정규식으로 작동하므로 `NPU_ACCELERATED`로 설명하면 안 된다.
