# Scenario Network Mapping · 4D Ontology · Red-Team Arena

현재 프로젝트의 검증 네트워크는 합성 경고 사례와 모델 스텁 경로를 대상으로 한다. 실제 피해 감소율을 측정한 적이 없다.

## 엘렌코스 질문

**반복 전제:** “모델이 위험 단어와 화행을 구별하고 0.70 이상 확률을 출력하면 신뢰할 만한 안전 경고가 된다.”

**반례:** 같은 “송금”이라는 말이 정상 은행의 피해 예방 교육 발화에 나오고, 공격자는 명시적 송금 단어 없이 “자산 보호 절차를 준비하라”고 압박한다. 추론 모델이 전자에 확신하고 후자에 침묵한다면 내부 일관성과 실제 안전성 중 무엇을 입증한 것인가?

**답:** 모델의 주어진 선택지 내 출력 동작을 입증했을 뿐이다. 독립 외부 데이터에서 화행·오탐·미탐·보류·지연·업무방해의 비용을 검증해야 한다.

## SNM 노드

- S0: 정상 금융 상담(행동 단어 없음) → NO_STRONG_SIGNAL + 안전 보증 부정
- S1: 직접 송금/OTP 요청 → PAUSE_AND_VERIFY; 사기범 확정 아님
- S2: 위험 단어 포함 교육/부정 → NO_STRONG_SIGNAL 또는 모델-반례 모순 시 ASK_HUMAN
- S3: 인용/신고 → CAUTION; 신고자를 사기범으로 오인하지 않음
- S4: 간접 압박·모호한 행동 → ASK_HUMAN; 대화 상태의 추가 문맥 필요
- S5: 높은 모델 선택확률·키워드 부재 → ASK_HUMAN; 환각된 근거 차단
- S6: 모델 장애·잘못된 스키마·지연 → ASK_HUMAN
- S7: 입력 변경 중 늦은 응답 도착 → STALE_VERSION 거절; 이전 결과가 최신을 덮어쓰지 않음
- S8: 중첩된 모순 주석 → ASK_HUMAN
- S9: 모델의 명시적 경고를 직접 지시로 오분류 → ASK_HUMAN
- S10: 동일 입력 중복 전송 → 단일 이력과 멱등 응답

## 네 차원의 연구 축

- **구조:** 발화·화자 주장·모델 선택·근거 앵커·정책 안내·현실 행동을 구별한다.
- **시간:** 최신 턴 ID·버전·TTL·모델 지연·상태 재평가를 독립 개체로 다룬다.
- **관점:** 사기 예방의 잠재 가치와 정상 업무 방해·경고 피로·프라이버시의 비용을 함께 측정한다.
- **방향:** UI 결정 → 정책 이유 → 신뢰경계 → 요청/응답 스키마 → 정확한 발화 구간까지 양방향으로 추적한다.

## 대회용 Red-Team Arena 체험

심사위원이 합성 카드에서 직접 지시·정상 업무·금지 교육·신고 인용 사례를 고른다. 보호 화면에서는 네 가지 권고 중 하나와 독립 확인 방식을 보여준다. X-Ray 화면에서는 실제 모델 응답이 있을 경우에만 질문별 선택확률과 지연을 표시한다. 모델이 없으면 수치를 나타내지 않는다. 사람이 편집한 입력은 기존 주석을 폐기한다.

## 독립 평가 프로토콜

분석 단위는 문장 단독이 아니라 대화/시나리오 패밀리이다. 패밀리 단위의 개발·검증·잠금 시험 분할을 강제한다. 목표 후보: 위험 대본 보류율 ≥90%, 정상 대본의 PAUSE_AND_VERIFY 오탐률 ≤10%, 인간 검토율과 지연 p50/p95 보고. 수치 목표는 실증값이 아니라 연구 수용 기준 후보이며 별도 검증·수정 전까지 성과 주장을 하지 않는다.
