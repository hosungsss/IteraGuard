# 의심계 v5.0 구현·디버깅 보고서

작성일: 2026-11-04 KST. 상태: DEVELOPMENT_CANDIDATE. 원본 v4.9와 이전 실험 증거는 보존하고 별도 작업본에서 구현했다. 이 보고서는 코드를 고쳤다는 사실과 판단 성능이 좋아졌다는 주장을 구분한다.

## 1. 구현 결과

공통 판단 계약을 Python과 브라우저 JS에 추가했다. 질문 7개·선택지 순서·정책·템플릿/코드 지문·실행 설정을 묶어 서로 다른 실행면이 같은 입력 계약인지 확인한다. 현재 턴 판단 후 사용자 검토 요청과 오프라인 LinkGuard를 같은 순서로 적용한다. 앱과 아레나의 Typed 기본은 기존 legacy로 맞췄고 DRA는 비교 후보로 표시한다. 0.70이나 DRA 비용표를 임의 조정하지 않았다.

실행 trace는 조건이 참인 것, 현재 우선순위에서 적용 가능한 것, 실제 적용한 규칙, 최종 행동을 따로 기록한다. q_evidence뿐 아니라 다른 보류 조건이 동시에 충족됐는지 확인할 수 있다. 모델 T=1.52는 로컬 제공자 설정이며, evaluator가 모델 신원을 인증하거나 사기 도메인 확률을 보정했다는 뜻이 아니다.

아레나는 OPEN과 CLOSED_UNRESOLVED를 지원한다. 미해결 상태로 보관한 뒤 이전 이력을 유지한 채 재개할 수 있다. 현재 턴 모델 안내, 세션의 과거 위험, 확인 작업의 사용자 보고를 분리한다. 확인했다고 보고해도 prior_pause를 지우지 않고, 반복되는 과거 위험 보류만으로 같은 확인 작업을 무한 생성하지 않는다. 새 위험 문장이나 강해진 위험에는 작업을 다시 만든다. 종료/재개도 요청 ID·버전·멱등성 검사를 받는다. SQLite v4 스키마는 이력을 보존하는 추가 마이그레이션을 적용한다.

단문 PC 앱/PWA/APK는 현재 문장만 판단하는 도구다. 이 앱의 문장별 기록을 아레나의 위험 유지 세션으로 오해하지 않도록 입력·결과·기록 화면에 범위를 표시한다. 주력 지속 세션은 아레나다. NLP indicator는 기기 내 NLP 전용이며 실제 Zoro 경로와 같은 모델/전체 파이프라인으로 세지 않는다.

제품 v5 relay는 loopback 전용으로 제한했다. 원격 허용 환경 변수로 이를 우회하지 않는다. 데스크톱 relay는 비동기 요청 시작 때 endpoint/model 설정을 고정해 처리 중 설정 변경으로 모델 확인 기준이 뒤바뀌지 않게 했다. 한글 2,000자가 5KB body 한도에 걸리던 입력 계약 오류는 실제 바이트 크기 제한과 함께 수정했다.

세션 trace의 input_fingerprint는 text만의 해시가 아니라 version/text/task/관측/검토옵션을 묶은 요청 HMAC이다. 작업 중복 억제에는 별도 text HMAC을 사용한다.

DB trace에는 원문·인용·URL을 저장하지 않고 링크 집계만 남긴다. 확률 분포·근거 offset·요청/작업 ID·사용자 관측은 파생정보로 보관한다. 원문 없는 trace로 원문 재생을 보장하지 않는다. 실기관 확인·외부 평판조회·은행/전화 제어는 수행하지 않는다.

## 2. 실제 조로 질문별 실험

기존 V2 48개(빈 입력1개는 추론 제외), 기존 AI25, 새 AI 개발25를 사용했다. 원본 질문과 action_only/speech_only/evidence_only의 네 조건에서 같은 비어 있지 않은 97개를 새로 호출해 **388/388 VALID**, 실패 0을 확인했다. 원본72 재호출의 정규화 확률과 두 정책 action/reason은 이전 증거72/72와 일치했다. 모델 export 해시도 동일했다. 선택지 순서·온도·정책을 바꾸지 않았다.

새 25개는 정상12·위험10·맥락부족3이며 요구 행동/화행/위험/허용 안내/필수중단/근거를 별도 주석했다. 사용자 요청에 따라 AI가 초안을 만들고 평가에 사용했으므로 독립 인간 평가가 아니다. 기존 AI-JM-02 주석의 모호성은 audit로 남기고 원본을 고치지 않았다.

| 질문 조건 | 새25 legacy 기대 일치 | 새25 DRA 기대 일치 | 채택 판단 |
|---|---:|---:|---|
| 원본 | 14/25 | 17/25 | 제품 유지 |
| action만 변경 | 14/25 | 16/25 | HOLD: DRA 새 자격증명 요구의 필수중단 PAUSE→ASK 회귀 |
| speech만 변경 | 17/25 | 17/25 | HOLD: 기존 V33 legacy PAUSE→ASK 회귀 |
| evidence만 변경 | 16/25 | 20/25 | HOLD: V02 DRA 경고문의 ASK→CAUTION 과개입 |

전체 문장별 개선/회귀·정상 보류·위험 누락·항상ASK 비교는 실험 JSON에 전수 보존한다. 일부 기대 일치 증가를 제품 채택 근거로 사용하지 않았다. action/speech 질문 하나를 바꿔도 다른 head 확률이 94~97개 사례에서 함께 변했다. 따라서 '질문 하나 변경'과 '독립 head 하나의 효과'는 다르다. evidence 변경은 나머지6개 head의97개 확률을 보존했다.

## 3. 아직 남은 문제와 판단

정상 안내의 근거 부족, none+direct_request 충돌, 정상 송금과 위험 송금의 구별, 낮은 confidence에 의한 보류는 아직 남는다. 현재 모델+정책은 짧은 문장만으로 많은 것을 보류한다. 질문 문구만으로 해결하지 못했으며, 비교한 정책 중 필수중단→보류나 과개입 회귀가 생겨 사전 채택 기준을 통과하지 못했다. 다음 성능 변경은 요청 유무와 민감행동 분리 등 새 schema/rubric 후보를 먼저 잠그고, 새 독립 데이터로 확인해야 한다.

별도 reasoning LLM 미들웨어를 지금 필수로 추가할 근거는 없다. 이번 공통 계약 모듈이 정규화·정책·후처리·추적을 담당한다. 추가 모델은 새로운 지연·비용·오류를 가져오므로 동일 개발/잠금셋에서 유익함을 보여야 한다.

독립 인간 평가, Android 실기기 설치/실행, iOS, 새 네이티브 크로스컴파일 실행, 대회 참가/IP/세부 팀 합의는 이번 구현 성공으로 대신하지 않는다. L2본문/GOLDEN-V33-G7/기관 질문/진명L1의 구체 승인을 추정하지 않았다. 의심계 외 아이디어와 과거 교재 미확보 항목도 완료로 바꾸지 않았다.

## 4. 검증과 배포

최종 소스 회귀와 실제 로컬 실행을 확인했다. 최초 전체 검사에서 v49 1건이 실패했으며, 배포 도구 import가 제품 LinkGuard를 가리는 sys.path 오염이 원인이었다. 도구를 import-safe하게 수정하고 새 회귀를 포함한64건이 통과했다. 초기 실패 로그도 삭제하지 않았다. source unit/UI/parity와 실제 Typed HTTP/browser, APK 정적/서명, 실기기 실행은 서로 다른 검사다. 재생 검사의 호출 수를 실제 추론 횟수에 합산하지 않는다.

현재 PWA/APK/스킬/FULL 후보는 tools/build_distribution_v50.py 및 build_release_v50.py로 생성한다. 빌드 자산 지문과 FULL manifest를 확인하고 생성된 오래된 바이너리가 소스 검사 성공을 빌려 통과하지 않도록 한다. Android 디버그 인증서는 매 빌드 새로 생성하므로 바이너리 bit-for-bit 재현성을 주장하지 않는다.

## 5. 전체 계획 추적

원래 33요구사항·12충돌·8결정·13게이트·8개 P0 번호를 docs/V50_TRACEABILITY.json에 모두 보존했다. 항목을 삭제해 완료율을 높이지 않는다. 현행 코드/계약은 README, CURRENT_PROJECT_STATE, PRD_v50, SYSTEM_PROMPTING_v50를 우선하며 이전 버전 문서는 역사로 남긴다.

실제 제공자 요청은 이번 작업 총399회(질문388+재시작4+브라우저7)이며 유효 수용398회다. 브라우저 최초1회는 실행명령에 모델명 필드가 빠져 로컬 export 이름이 반향돼 MODEL_ID_MISMATCH로 거부됐다. 숨은 대체판단 없이 보류한 것을 확인하고 DMSG_SEND_MODEL_FIELD=1 및 DMSG_REQUIRE_MODEL_ECHO=1을 실행명령/README에 추가했다. 실패를 질문388회 실패로 섞거나 전체성공으로 숨기지 않았다.

브라우저에서는 보관·재개·다른 세션 전환·기존 기록 복원까지 확인했다. 마지막 아레나 상태는 v9, prior_pause=true이며 정상 안내문 현재턴은 NO_STRONG_SIGNAL, 세션 안내는 ASK_HUMAN이다. 확인 보고는 REPORTED_COMPLETE로 유지되고 작업은 자동 중복생성되지 않았다. 이는 정상문장 자체를 위험이라고 모델이 판단했다는 뜻이 아니다. 단문 앱은 별도로 현재 요청을 실제Typed로 분석해 PAUSE_AND_VERIFY를 표시했다.

추가로 화면에 남은 v4.9/RTX3060 생성실험 설명을 v5 Typed 실행 범위로 갱신했고, 현재 소스의 24,488/221/49 검사 결과를 빌드 정보와 연결했다. 마지막 변경 후 UI14·금지문구와 최신 APK 서명/자산을 다시 확인했다. 두 브라우저 콘솔 오류는0이었다.

원 실험의 raw·프로토콜·입력·실행 당시 runner는 internal/evidence/v50/question_ablation에 묶었다. 이후 standalone 입력 경로 개선 runner와 원 실험 runner를 구분하며, 승인 모델 가중치는 포함하지 않는다. SQLite 검증 DB와 자격증명도 FULL에 포함하지 않는다. 상세 원실행 로그/스크린샷/전체 배포 검사는 별도 deliverables/v50_implementation_20261104에 있다.

독립 패키지의 개발 프로토콜 준비: `python -m experiments.v50_ablation prepare --output runs/v50_ablation_offline`. 가중치가 없으면 MODEL_EXPORT_NOT_REGISTERED로 준비만 가능하고 run은 거절한다. 실제 모델을 재등록할 때 `--model-dir /path/to/Zoro-1-kev`와 새 output을 지정한다. `--input-dir /path/to/replay_inputs`를 지정할 수도 있다. 원388회 실험의 프로토콜을 덮어쓰지 않는다.
