# 의심계 UI 상태 분리 해결 솔루션

작성: 2026-11-19 KST. 상태: 구현 전 계획. 사용자 승인 범위: 표시 계층 개선, 새 분석 진입점, 검증 후 커밋·푸시. 판단 정책 변경 없음.

## 목적
현재 문장 분석 결과와 이전 미해결 상태를 각각 표시하고, 기본 메시지·다음 업무·보조 경고에서 반복되는 경고를 하나의 다음 행동으로 통합한다.

## 설계
1. 서버의 action, current_turn_action, current_turn_reason, reason, prior_pause, model_status 및 업무 목록을 그대로 사용한다. 표시 문구만 재구성한다.
2. 현재 문장의 의미적 보류, 모델 오류, 이전 위험 유지, 사용자 검토 요청을 구분한다. 처리 완료와 의미적 판단 확정을 혼용하지 않는다.
3. 결과는 제목 / 이번 문장 / 이전 미해결 사항 / 다음 행동으로 구성한다. 이전 업무의 구체적 내용은 실제 저장된 항목으로만 표시한다. 현재 발생한 업무를 전부 이전 업무라고 부르지 않는다.
4. 다음 행동은 한 영역에만 표시한다. 현재 입력에 근거 없는 OTP·앱 설치 등을 포괄적으로 나열하지 않는다. 근거가 부족하면 요청 내용 확인으로 안내한다.
5. 별개의 메시지 분석 시작 버튼은 새 세션을 만들고 입력·현재 결과를 초기화한다. 이전 세션·업무·위험 상태를 삭제하거나 해결 처리하지 않는다. 실행 중에는 비활성화하며 실패 시 기존 세션을 유지한다. 이전 기록으로 돌아갈 수 있는 진입점을 제공한다.
6. 원문·모델 응답을 사실 확인 또는 안전 인증으로 승격하지 않는다. 정책과 감사 데이터의 의미는 변경하지 않는다.

## 검증
- 위험 요청 후 정상/불명확 문장: 현재 판단과 이전 상태 분리.
- 모델 실패와 이전 위험 동시 존재: 기술 실패와 미해결 상태 모두 표시.
- 입력 수정/지연 응답: 오래된 결과가 새 입력에 표시되지 않음.
- 새 분석: 이전 기록·열린 업무 보존, 새 세션 구분, 실패 시 기존 상태 보존.
- 중복 경고 제거, UI 상태와 서버 행동 코드 동일성.
- 기존 회귀 검사 및 실제 브라우저 크기별 입력/붙여넣기/판단/새 분석 동작.
- 통제 응답과 실제 Zoro 검증을 구분한다. 공개 사이트 배포는 별도 권한 확인이 필요하다.

## 작업 순서
최신 소스 확인 → 표시 계층 통합 → 새 분석 버튼/기록 진입점 → 회귀·브라우저 검증 → 변경 이력과 라이선스 목록 점검 → 커밋·푸시.

## 미검증
이 문서 작성 시점에는 구현·테스트·실제 Zoro 재실행·공개 사이트 반영이 완료되지 않았다.
