# 현행 보안·근거·NPU 검증 설계 (2026-11-01 KST)

**목적**: 제품을 안전하다고 단정하는 것이 아니라, 실제 실행에서 반박 가능한 보안 경계와 모델 실행 가능성을 명확하게 관리한다. 기술 스택이나 방향이 바뀌어도 이 원칙은 유지한다.

## 1. 핵심 검증 질문

> 모델이 높은 확률로 `none`을 선택하면서 `q_pressure`에는 높은 확률을 부여하면 시스템이 안전하다고 표시해도 되는가?

**아니다.** 다만 압박 확률만 높다고 정상 거래를 위험한 것으로 강제 분류해서도 안 된다. 현행 정책은 원문에 명시적인 긴급·강요 단서가 함께 있는 경우 모델 내부 모순을 이유로 판단을 보류한다. 판단 보류는 사기 확정이나 범죄 위험도 검증과 다르다.

## 2. SNM — 시나리오 네트워크의 관찰 기준

| ID | 초기 상황 | 변형·위협 | 기대 결과/관찰 방법 | 남는 한계 |
|---|---|---|---|---|
| S01 | 정상 안부 | 모델이 이유 없이 `q_pressure=.9` | 직접 압박 표현이 없으면 단독 보조 신호만으로 고위험 경고를 발생시키지 않음 | 모델의 오류 원인 설명 불가 |
| S02 | 우회적 요청 | `q_action=none`, 압박 YES, `지금 바로` | 모순 탐지 → `ASK_HUMAN`; synthetic test | 우회 표현 전수 탐지 불가능 |
| S03 | 직접 송금 | `q_action=transfer`, 직접 요청 | 앵커 + 모델 가정 시 `PAUSE_AND_VERIFY` | 모델 정확도 미검증 |
| S04 | 경고/인용 | `송금하지 마세요`, `송금하라고 했대` | 직접 위험 지시로 강제 확정 금지 | 복합 발화 분절 미완료 |
| S05 | 기관 사칭 | 발신자 `OO은행입니다` | 자칭과 실인증 구분 | 신원인증 기능 미구현 |
| S06 | 모델 장애 | 연결 끊김/비정상 JSON | `ASK_HUMAN`; 예전 결과 지우기 | UX 실브라우저 검증 필요 |
| S07 | 지연 응답 | 턴 N 응답보다 N+1 먼저 완료 | N 결과 커밋 차단 | 분산 서버 보장 없음 |
| S08 | 외부 원격 | 운영자 동의/allowlist 없음 | 전송 차단 | 실제 개인정보 적법성 별도 |
| S09 | DNS 혼합 | A레코드 공인+내부 IP | 전체 연결 차단 | DNS 공급자 자체 인증 아님 |
| S10 | DNS 재결합 | 사전 공인 IP, 실제 연결 때 내부 IP 변경 시도 | 검증된 IP로 직접 연결, TLS SNI는 원래 호스트 | 실운영 침투 테스트 미완료 |
| S11 | 단문 개인정보 | 사용자의 짧은 입력이 해시로 로그에 남음 | 원문 일반 SHA 대신 프로세스별 HMAC | 메모리 공격·복구키 영속성 미보장 |
| S12 | 성능 분석 | 같은 시나리오 변형을 dev/lock에 섞음 | 분할 오염으로 평가 중단 | 외부 정답 라벨 없음 |
| S13 | NPU 주장 | 운영체제에 NPU 장치가 표시됨 | `NOT_VERIFIED` 유지 | 모델 자체 NPU 변환·실행 미실시 |
| S14 | 하드웨어 변경 | NPU 실행 불가·CPU/GPU만 가능 | 오프라인/실기기 주장 보류 | 실기기 프로파일 없음 |
| S15 | 합법 업무 | 과잉 경고로 정상 행동 중단 | 정상 업무 방해율을 따로 집계 | 실제 현장 오탐률 없음 |
| S16 | 새 제품 선정 | PAYLOCK/STOPLINE/LEAKLESS로 변경 | 명시적 공동 결정 후 PRD·정책·모델질문·데이터·UI 전부 재설계 | 팀 합의 미확인 |

## 3. 4D Ontology — 구조/시간/관점/역검증

- **구조:** `Utterance`, `ModelOutput`, `Claim`, `EvidenceSpan`, `PolicyDecision`, `Advisory`, `UserAction`, `Checkpoint`, `HardwareBackend`는 별개 개체. `MODEL_ASSERTS`를 `FACT_VERIFIED`로 자동 전환하지 않는다.
- **시간:** 입력 수신 시각·모델 요청 시각·응답 시각·세션 버전·키 생성 시각·근거 주석 시각·평가셋 잠금 시점을 따로 기록. 늦은 모델 결과가 최신 세션을 덮어쓰지 않아야 한다.
- **관점:** 잠재적 피해자, 정상 사용자, 재무/보안 담당자, 연구자, 모델 개발자, 심사위원은 성공 기준이 다르다. 위험 미탐과 정상 업무 중단을 함께 보여 준다.
- **방향/역검증:** 원문→모델의 typed label→원문 앵커→독립 정책→가상 안내→실제 측정 여부. 역방향은 UI 권고→reason code→모델 후보/출처→문자 구간→입력 세션→테스트/증거.

## 4. NPU 실행의 증거 단계

1. **N0 장치 탐색:** CPU/GPU/NPU 하드웨어 종류, 운영체제, 드라이버와 실행 공급자 명단 확인. 모델 실행 증거 아님.
2. **N1 가중치와 형식:** 실제 모델 revision/hash, 사용 허가, 양자화 파일, 연산자 지원 및 typed decision head 보존 검증. 공개 모델 카드만으로 확인 불가.
3. **N2 정확한 런타임:** 동일 결과를 CPU 또는 GPU 기준과 비교하며 지정 execution provider에 실제 커널 배정된 증거를 캡처. 자동 CPU fallback은 NPU 성공이 아님.
4. **N3 품질:** 비정량화 대비 품질 변화, 한국어 시나리오 계열별 정확성, 선택확률 보정, 예상 밖의 입력 제약을 측정.
5. **N4 성능:** 워밍업·모델 로딩·선택결정·추론 재호출·전력의 단위를 분리하고 n, p50·p95, 최악 지연과 장비 정보를 기록.
6. **N5 운영:** 연속 실행, 열 스로틀링, 배터리·메모리, 오프라인 네트워크 차단 상태, 패키징과 설치까지 재검증.

지금 가능한 검사는 `python dmsg/scripts/npu_readiness.py`를 통해 **N0 일부만 수집**하는 것이다. 실제 NPU 추론은 실행하지 않았다.

## 5. 판정과 배포 금지사항

- `q_scam`의 선택확률을 실제 사기 발생 확률, 반올림된 위험도 또는 피해 예측 확률로 표현하지 않는다.
- 원격 서버의 `model` 문자열은 checkpoint 신원 확인이 아니다.
- 단일 모델의 스키마 통과와 실제 데이터 정답률을 혼동하지 않는다.
- 원격 TLS/IP 고정은 인증·부인방지·개인정보 처리 목적의 법적 승인이나 모델 진품 인증이 아니다.
- NPU 공급자 목록에 NPU를 표시해도 Zoro-1이 그 장치에서 구동됐다는 의미가 아니다.
- 사용자 최신 결정에 따라 Google Drive 쓰기를 하지 않는다.

## NPU 실행 가능성: 산술 하한과 남은 미지수

공개 모델카드(2026-11-01 확인)는 Zoro-1을 Qwen3.5-4B 파생, BF16 safetensors, 메타데이터상 약 5B 파라미터로 표시하고, 벤치마크는 서버당 H100 1장에서 수행됐다. ONNX·양자화·NPU용 산출물은 공개되지 않았다.

| 항목 | 값 | 성격 |
|---|---|---|
| 가중치 메모리 하한 (5B) | BF16 9.31 GiB / INT8 4.66 GiB / INT4 2.33 GiB | 산술, KV 캐시·런타임 제외 |
| 4초 타임아웃 충족 처리량 (900 토큰 가정) | 단일 prefill 225 tok/s, 질문별 prefill 1,350 tok/s | 요구치, 측정 아님 |
| 판정 연산 형태 | 생성 없이 prefill 1회 (trida 페이지) | 공개 설명 |
| typed decision head의 NPU 변환 | 미확인 | NOT_RUN |
| 양자화 후 확률 변화 | 미확인 | NOT_RUN |

판정이 생성(decode)이 아닌 prefill 중심이라는 점은 메모리 대역폭보다 행렬 연산 처리량이 지배하는 작업이라는 뜻이다[추론]. 그래서 NPU에 비교적 유리한 형태일 수는 있지만, 커스텀 판정 헤드를 NPU 런타임으로 옮긴 실행 기록이 없고 양자화가 확률 분포를 얼마나 바꾸는지도 모른다. 따라서 본선 시연의 기본 경로로 NPU를 전제하지 않는다. 실측 순서는 (1) 현장 노트북 CPU/GPU에서 kev로 `smoke_zoro.py` 지연 측정, (2) 그 결과로 타임아웃 확정, (3) 시간이 남을 때만 INT8/INT4 변환과 확률 차이를 같은 프로브로 비교한다.
