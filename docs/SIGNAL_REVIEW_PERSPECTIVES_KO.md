# 의심계의 네 가지 검토 관점

첫 화면에서 모델은 같은 원문을 한 번 받아 발신자가 요구한 행동과 피싱 의심 등급을 고른다. 네 역할은 각각 다른 오류를 찾아내기 위해 설계한 가상의 실무 관점이다. 한 모델에서 나온 선택을 네 전문가의 독립된 표결로 집계하지 않는다.

| 역할과 판단 대상 | 검토할 단서 | 오판을 막는 반대 질문 |
|---|---|---|
| 사이버 보안·금융 사기 분석가 · 자금과 권한의 이동 | 누가 누구에게 돈, 비밀번호, 인증번호, 원격접속 권한을 넘기라고 하는가? 기존 수취인 변경과 환급 조건부 선입금을 구별한다. 발신 표시명과 도메인 평판은 관찰 범위를 따로 본다. | 같은 행동이 예방 안내에 인용됐는가? 정상 대금 납부 요청에도 송금이라는 단어가 등장한다. |
| 행동 심리 검토자 · 확인을 포기하게 만드는 압박 | 위협이나 불이익이 어느 행동에 붙는지, 독립 확인을 막는지 본다. 기억을 부정하는 발언과 돈이나 접근 권한의 요구가 함께 있는지 살핀다. | 단순한 기한이나 정정 안내인가? 단일 문자로 반복적 가스라이팅, 발신자의 의도, 정신 상태를 판정할 수 없다. |
| 소비자 보호 조사관 · 약관 주장과 근거 | 누가 적용을 주장한 조항인지, 금액·상대방·발생 조건이 적혔는지 본다. 약관 설명, 동의 요구, 실제 지급 요구를 구별한다. | 계약 원본과 적용 시점이 있는가? 발신자가 “의무”라고 쓴 것만으로 위법성·채무·환급 권리를 확정할 수 없다. |
| 취약 이용자 대변인 · 수신자가 이해할 행동 | 처음 읽는 사람이 ‘누가 누구에게 무엇을 요구했는가’를 쉬운 말로 다시 설명할 수 있는지 확인한다. 화면이 잘리거나 주어·행동이 빠졌을 때 추측하지 않는다. | 발신자의 지시가 앱의 권고처럼 보이는가? 나이·장애·서툰 문체는 위험 판단의 증거가 될 수 없다. |

**의견이 갈릴 때.** 먼저 현재 수신자에게 요구한 행동을 정한다. 예방·과거 인용·조건 설명을 분리한다. 실제 요청은 구체적이지만 계약의 효력이나 사기 여부가 미확인일 수 있다. 그때 행동 선택은 보존하고 의심 등급은 명시된 근거로 고른다. 행동이 모호하면 기존 unknown을 쓴다. 정규화 이후의 기존 모순 보정과 원점수 보존 규칙은 그대로 적용한다.

## 검토자가 대조할 합성 사례

| 쌍 | 입력 A / 입력 B | 비교할 결과 |
|---|---|---|
| 보안 | “은행은 인증번호 전달을 요구하지 않습니다.” / “이번 환급 인증번호를 저에게 알려 주세요.” | A의 안내를 전달 요구로 오인하는지, B의 현재 요구를 share_auth_secret로 포착하는지 본다. |
| 압박 | “오늘까지 참석 여부를 회신해 주세요.” / “기억이 틀렸습니다. 은행에 확인하면 환급을 취소합니다. 새 계좌로 보내세요.” | 회신 기한과 확인 방해를 구별한다. B는 변경 계좌 송금, 두 문장 모두 심리 진단 대상이 아니다. |
| 계약 | “계약서에는 보증금 반환 조건이 적혀 있습니다.” / “환급을 받으려면 보증금을 먼저 입금하세요.” | 설명만 있는 A는 no_request, B는 pay_unlock_fee. 어느 쪽도 계약의 적법성 증거가 되지 않는다. |
| 이해도 | “그거 처리 좀 해 주세요.” / “견적서를 작성해 회신해 주세요.” | A는 unknown, B는 prepare_or_submit_documents. 개인 특성을 바꾸어도 같은 요구의 해석이 유지되는지 확인한다. |

이 사례는 설계 검토용이다. 성능 비교 시에는 예문과 겹치지 않는 새 입력을 독립적으로 라벨링하고, 같은 체크포인트·decision head·입력 순서에서 기존 지침과 새 지침을 각각 실행한다. 현재 행동 일치율, 위험 요청 누락, 정상 문자의 과잉 경고, 보류와 지연을 별도로 기록한다. 사용자 이해도는 실제 이용자가 화면을 보고 발신자의 요청과 다음 행동을 각각 설명하는지 관찰해야 한다.

## 구현과 재현

- PER-1~4. arena/review_perspectives.py의 행동·위험 지침을 arena/signal.py에서 q_action·q_signal에 배치한다. 별도로 요청한 링크 보조 의견만 arena/link_review.py의 q_review에 두 지침을 재사용한다.
- PER-5. tests_v56/test_signal_http.py에서 모델에 전달된 문항, 출력 키, 원문 보존, 1회 호출을 검사한다. tests_demo_validation/test_api_ui.js는 모순 보정 설명이 화면에 남는지 검사한다.
- 링크 화면은 /link-review, 상세 화면은 /arena다. 서버에 DMSG_PHISHTANK_CSV 및 시간대가 포함된 DMSG_PHISHTANK_AS_OF를 설정하면 최근 24시간 이내 운영자 제공 CSV를 대조한다. 외부 조회를 쓸 때만 DMSG_LINK_REVIEW_EXTERNAL=1 및 SCAMADVISER_API_KEY를 설정한다. 사용자가 지정한 호스트만 공급자 캐시에 질의한다. 로컬 보조 의견은 선택 사항이다.
- 복구 시 통합 PR의 병합 커밋을 별도 PR로 revert한다. DB 마이그레이션은 없다.
