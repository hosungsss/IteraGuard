# 현행 의심계 SNM·4D 위험 지도 및 수용 게이트

이 문서는 현재 시연/개발 상태와 앞으로 검증할 조건을 분리한다. `SNM`과 `4D Ontology`는 프로젝트 내부의 분석 프레임이며, 그 자체가 검증된 보이스피싱 감지 알고리즘은 아니다.

## 핵심 정책과 관점

- 판단 대상은 실제 범죄 확정 여부가 아니라, 입력 문장에 포함된 **사람의 행동 요청**과 **직접/인용/부정/불명확한 화행**이다.
- 모델 출력은 독립 정책의 입력 자료일 뿐 인증된 사실이나 외부 실행 권한이 아니다.
- 허용된 안내: `NO_STRONG_SIGNAL`, `CAUTION`, `PAUSE_AND_VERIFY`, `ASK_HUMAN`. 어느 것도 전화·금융기관에 실제 명령을 전송하지 않는다.
- 반례를 찾기 위한 작성자 합성 테스트는 도메인 정답률·사기 피해 감소 근거가 아니다.

## SNM 경로별 수용 기준

|---|---|---|---|---|---|
| SNM-D1 | 피해 가능 이용자, 직접 송금 요구 | 모델 직접요청·원문 앵커 일치 | `PAUSE_AND_VERIFY` | 작성자 모의 응답 + 단위 테스트 | 실제 모델 문맥 분해·정밀도 측정 |
| SNM-N1 | 정상 은행 상담의 송금 예방 교육 | 모델이 직접요청이라 오분류 | `ASK_HUMAN` | 합성 문맥 충돌 테스트 | 정상 대본 오탐 비용 측정 |

| SNM-U1 | 행동 요청은 간접 표현 | 사전 앵커 부재 | `ASK_HUMAN` | 합성 조건에서 동작 | 우회 미탐률·사전 밖 표현 수집 |

| SNM-IO2 | 외부 서비스가 악성 JSON 반환 | 중복 키/비JSON/초과 본문 | 거부/보류 | 루프백 HTTP 모의 테스트 | 실제 서빙 도구 버전별 계약 테스트 |
| SNM-T1 | 옛 모델 요청이 처리 중 | 새 사용자 턴 먼저 기록 | 옛 결과 커밋 거부 | 스레드 경쟁 테스트 | 다중 프로세스·장시간 부하 |

## 4D Ontology

**구조:** Caller/Utterance/RequestedAction/SpeechAct/ModelQuestion/ModelProposal/PolicyResult/EvidenceSpan/UserAdvice를 각각 독립 엔티티로 취급한다. 기관 자칭과 신원 인증은 별개이다. `text[start:end]==quote`는 문자 증명이지 의미 증명은 아니다.

**시간:** 입력 턴 버전, 모델 추론 시작·반환, 감사 해시, 확인 계획, 모델 후속 발화의 시각이 경쟁한다. 늦은 판단은 새로운 턴에 우선하지 못한다. 실제 분산 시스템의 시간 동기화까지 검증된 것은 아니다.

**관점:** 잠재 피해자에게 필요한 멈춤 안내와 정상 금융업무 사용자의 과잉 경고 비용을 함께 본다. 팀·운영자·심사위원은 실제 모델과 작성자 모형을 구별해야 한다.

**방향·역검증:** 발화 → 모형 응답 → 검증 규칙 → 정책 결과 → UI 메시지를 추적한다. UI 경고 → reason code → 원문 근거와 출처 → 정책/테스트 로그로 돌아오는 역방향 증거 체인을 유지한다.

## 최우선 미검증 요구

1. 실제 Zoro-1 체크포인트/revision·`/v1/systemone` 응답 계약을 동일 실행 환경에서 확인.
2. 한국어 대화 3종 이상(직접 요구·인용/경고·간접/정상 상담)을 개발·보정·잠금셋으로 가족 단위 분리.
3. TP/FP/FN/TN 및 `ASK_HUMAN`을 독립 산출하고 정상 오탐 비용과 위험 미탐 비용을 별도 기술.
4. 0.70 모델 라벨 선택 문턱을 실제 정답률이나 사기 사건 확률로 오인하지 않도록 보정·ablation 실험.
5. 실제 오프라인 장비, 브라우저, 접근성, 재시작·분산·네트워크 실패 시연을 측정.
6. 원격 모델 전송 시 운영자 동의에 더해 개인정보·출처·저장 위치·제3자 처리 약관을 검토.

## 유용한 반박

“확률이 높으면 틀릴 일이 적다”는 명제는 데이터셋·모델 보정·분포 이동이 알려졌을 때만 검증 가능한 가설이다. 행동 단서가 명백한 입력을 모델이 `none` 또는 `warning`으로 잘못 인식하는 반례는 이 명제를 무너뜨린다. `ASK_HUMAN`의 보수적 처리는 통제이지만 실제 의미 분류 개선은 아니며, 보류율이 지나치게 높으면 제품의 실용성이 떨어진다.
