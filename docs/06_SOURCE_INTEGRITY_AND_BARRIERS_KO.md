# 의심계 — 출처 무결성 및 기술 수용 조건

기준일: 2026-10-28 | 적용 범위: 해커톤 Track 1 합성 시연

## 자료의 신뢰도 계층

| 자료 | 확인할 수 있는 내용 | 제한 |
|---|---|---|
| 제품 명세서·System Prompt | 합의 대상 기능, 규칙, 수용 기준 | 실행 증거가 아님 |
| 실행 가능한 코드 | 로컬 로직과 테스트 대상 | 외부 모델의 정체성을 증명하지 않음 |
| 주최 측 공식 안내 | 행사 주제, 일정, 지정 조건 | 세부 현장 인프라·API 계약은 별도 확인 |
| Trida Zoro-1 공식 기술 문서 | `noul`·`choice`·`score`와 `/v1/systemone` 요청 예시 | 도메인 실측 성능이나 현재 서버 사용을 자동 증명하지 않음 |
| 합성 시나리오 | 설명 가능한 시연과 테스트 | 모집단 정확도·오탐률·피해예방 효과가 아님 |
| 모델 API 호출 | 확인된 endpoint에 대한 HTTP 응답 | 모델 체크포인트·서버 신원에 대한 독립 인증이 아님 |

## 제품에 적용하는 기술 원칙

- SRE·스마트팩토리·사기 대응을 한 화면에 섞지 않고, 정책 엔진의 **승인/실행 분리**, 제약 위반 시 안전 정지, 멱등성, 상태 전이, 감사 추적, 결과와 효과의 별도 검증을 범용 아키텍처 원리로 사용한다.
- 엔지니어링 문서의 수학적 예시와 진짜 모델 학습·추론에서 관측한 로짓은 별도의 범주다. 예시 보정 온도를 한국어 보이스피싱 도메인에 검증 없이 재적용하지 않는다.
- `REQUESTS`/`REPORTS` 등의 온톨로지 관계는 발화에 대한 **출처가 붙은 의미 주석**으로만 저장한다. `Caller IS_CRIMINAL`, `Account IS_FROZEN`, `Bank IS_VERIFIED` 등 외부 세계 사실은 작성하지 않는다.
- UX는 사용자 행동 카드와 연구자 검증 정보 영역을 분리하되, 데모 상 과장된 실제 송금 차단·휴대전화 제어 등을 표현하지 않는다.
- README, PRD, System Prompt, 설치 가이드는 언제나 현행 프로그램의 상태만 설명한다. 연구 주장·실측 결과·수용 상태는 각각 확인 가능한 증거를 필요로 한다.

## 검증해야 할 외부 의존성

1. 주최 측에서 지정한 모델 체크포인트와 라이선스, 사용 가능한 `kev` 버전, GPU 제공 조건, `/v1/systemone` 실제 응답 구조.
2. API Key 발급 여부와 외부 연결 정책, 응답 지연·동시 처리 및 실패 정책.
3. 사전 제작 코드·외부 서비스·데모 모의행동의 허용 범위.
4. 독립 한국어 정상/위험/모호 상황의 표본 수, 정답 주석 일치도와 시나리오 패밀리 분리.
5. 3인 팀의 신청 완료, 역할·기여도·IP 관련 실제 합의.

## 설계 참고문헌 및 적용 경계

- Bojie Li, 『AI 에이전트를 깊이 이해하기』 한국어 PDF v2.0 (2026-09-23): 하네스, 출처와 내용 격리, 도구·실행 정책 분리, 실패 회복, 검증·제거 실험. 원저의 모든 수치나 제시 구현이 실제 의심계 지표로 재현된 것은 아니다.
- 손호성 박사님의 `agent-engineering-in-depth.skill`: 원본은 제3자의 방법론 참고자료. `dmsg`에 동일한 스킬을 재포장/개명한 것이 아니라 관련 방법론을 독립 구현했다.
- 「최적 주제 선정 — 기억 문지기 범위 정의서」: 기억 쓰기 직전 하나의 판정이라는 범위 제약, 신뢰 출처의 구조적 판별, 정규/적대 보존집합, 3개 동작 후보를 참고했다. 의심계를 기억 비서 서비스로 전환하거나 실제 메모리 쓰기를 제공하지 않는다.
- `PROJECT_INSTRUCTIONS_KO.md`, `SKILL_UPGRADE_PRINCIPLES_KO.txt`: `internal/source_material/team_governance`에 별도 보관하여 R01–R09, 기능 보존, 외부 attribution, Rollback, 스킬 고정 경로를 검사한다. 원본 외부 스킬 저작권·라이선스와 사용자의 기존 `dmsg` 정체성을 혼동하지 않는다.
