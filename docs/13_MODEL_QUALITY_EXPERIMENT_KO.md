# 의심계 실모델·화행 품질 평가 사양

## 검증 질문

- 모델 직접 판정이 사전 작성된 정책 라벨링보다 한국어 문맥 판정에서 실제로 나은가?
- 부정문과 인용문이 직접 위험 명령으로 오인되는 비율을 얼마나 줄이는가?
- 추가 추론은 동일 잠금셋에서 정확도·보류율·지연에 어떤 변화를 주는가? 아직 실제 코드 경로가 없으므로 미구현이다.
- 정상적인 금융 업무에 불필요하게 `PAUSE_AND_VERIFY`를 안내하는 비율은 얼마인가?

## 데이터 단위/누출 통제

검증 단위는 대화 세션 전체와 개별 발화를 구별한다. 같은 문장의 번역·어순 수정·화자 변경·금액 치환은 동일 family에 속한다. family 분리 없이 랜덤 분할하면 암묵적인 정답 누출이 발생할 수 있다. 개발/임계값 선택/잠금 평가를 분리하고 마지막 평가 데이터는 결정을 마칠 때까지 보지 않는다.

공공기관 예시나 온라인 데이터를 사용하면 재배포·사용 허가를 확인한다. 실제 전화번호, 계좌, 인증번호, 녹음 원문을 무단 수집하지 않는다.

## 권장 지표(실험 설계, 측정값 아님)

- 화행 혼동 행렬: `DIRECT_REQUEST`/`REPORTED_OR_QUOTED`/`NEGATED_OR_WARNING`/`UNCLEAR`.
- 행동 종류 혼동 행렬: 송금, OTP, 원격앱, 개인정보, 링크, 비밀유지, 없음·불명확.
- 정상 대화에서 최종 `PAUSE_AND_VERIFY`를 내는 비율(FPR)과 보류 비율.
- 위험 대화에서 필요한 경고를 내지 못한 비율(FNR). `ASK_HUMAN`은 별도 범주로 계산.
- calibration: Brier/ECE(정답 라벨과 유효한 표본이 있을 때만), 확률 임계값의 효과.
- 지연과 비용: 지연 p50/p95/최악, 샘플 n, 기기 CPU/GPU/VRAM, 오프라인/온라인 모드.
- ablation: 키워드/단일 typed/typed+컨텍스트 충돌 게이트/추론 후 재판정.

## 모델 출처·계약 게이트

- 서버가 반환한 `model` 이름과 실제 가중치 인증은 다르다. 체크포인트 ID, 해시, 제공자, 설치 경로, 운영 서버 상태를 구분한다.
- `q_action`, `q_speech`, `q_scam`, `q_claim`, `q_pressure`, `q_risk` 6개 질문의 공식 엔드포인트 실제 응답 구조를 그대로 기록한다. 현재 파서는 잠정 내부 envelope을 검사하므로 실모델에서 실패할 수 있다.
- `score`의 범주·수치 매핑과 `noul`의 의미가 서버 버전과 맞는지 별도 계약 테스트를 통과한다.
- 임계값 0.70은 내부 시연의 검증되지 않은 휴리스틱이다. 독립 도메인 보정 없이 정확도·사기 확률로 표현하지 않는다.

## 배포 증거 판정

현재 확인한 합성 fixture·모의 HTTP·제약 테스트는 E2-E3 수준의 근거이다. 실제 Zoro 가중치 식별이나 독립 평가(E4-E5)는 별도 실험이 필요하다. 실제 피해 예방(E6)은 법적/윤리적 승인과 현실 사용자 연구가 없는 한 주장하지 않는다.

참고: https://trida.trillionlabs.co/decision/ (공식 요청 형식 및 보정/선택적 추론의 일반 설명; 의심계 데이터의 실증은 아님).
