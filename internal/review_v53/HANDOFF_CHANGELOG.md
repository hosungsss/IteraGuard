# IteraGuard v5.3 검토 인계 기록

## 2026-11-19 — review 1.0

- 목적: Track 1 해커톤 제출을 위한 프로젝트의 경쟁력·실행 경로·검증 근거를 비판적으로 점검한다.
- 출처: 사용자가 지정한 Drive 프로젝트와 v5.3 폴더, 기존 v5.1 저장 실험, 현재 공식 Zoro/대회/비교 제품 문서.
- 원본: Drive 및 제품 소스는 수정하지 않았다. 필요한 파일은 검토용 복사본으로 읽었다.
- 생성: 검토보고서, 코드 재현 결과, 원자료 검산 결과, 재현 스크립트, 테스트 로그, 이 변경 기록.
- 확인: 활성 execution manifest 지문 일치; Python execution 13/13, profiles 12/12, Node UI 16/16 PASS. 합산 수치는 서로 다른 범주의 검사이며 모델 정확도 표본 수가 아니다.
- 새 재현: 이전 확인업무 완료 보고 후 다른 입력이 ASK이면 새 업무가 열리지 않는 경로.
- 조건부 재현: /v1/decide를 기존 클라이언트에 설정하면 네트워크 이전 INVALID_MODEL_ENDPOINT.
- 원자료: AI24의 라벨 해시·48개 raw·48개 결과를 대조, count와 사례 ID를 다시 계산해 기존 metrics와 일치 확인.
- 영향: 제출 전 수정 우선순위와 시연 설계를 구체화한다. 제품 동작 자체는 바꾸지 않았다.
- 미수행: 새 Zoro 추론, 실제 브라우저 렌더링, 사용자 발표 장비·모바일 실기기, 외부 기관/은행 연동, 제출.
- 재현: 동봉 스크립트의 첫 번째 위치 인자로 사용자의 v5.3 프로젝트 루트 경로를 전달한다. 제품 의존 파일의 원래 구조가 필요하다.
- 복구: 제품 변경이 없어 원본 복구가 필요하지 않다. 검토 산출물은 독립 사본이며 원본 버전 이력을 대체하지 않는다.
- 후속 변경: 수정안은 아직 제안이다. 실제 수정 시 별도 후보·기존 작동본을 유지하고 새 결과를 이 기록에 추가한다.

## 산출물 작성 중 보완

- 문서만의 성능 검토에서 원시 라벨·응답·결과 검산까지 범위를 확대했다.
- “v5.3 신규 모델 호출 0”과 “과거 v5.1 실제 실행 기록”을 구분했다.
- 후보 PAUSE 미달 2건이 모두 ASK라는 점을 원자료로 확인했다.
- 일반 경고와 새로 재현한 워크플로 결함, 서버를 교체할 때의 조건부 호환성 위험을 분리했다.
- 코드 재현 스크립트에 선택적 제품 루트 인자를 추가해 원본을 동봉하지 않고도 재사용할 수 있게 했다.
