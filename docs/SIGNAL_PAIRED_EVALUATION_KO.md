# 신호등 질문 개선 및 성능 검증

2026-11-20 KST · 기준 코드 1af8d50572b1444264fa2929140e3e42ac98fede

문자를 입력하면 Zoro가 원문으로 발신자의 요청과 의심 등급을 고른다. 운영자는 아래 세 설정을 같은 앱에서 비교할 수 있다. CPU 선분류·추가 모델·외부 검색 호출은 없다. 앱이 기본으로 사용하는 baseline의 질문 지문은 551건을 측정했을 때와 같다.

| 설정 | 무엇을 바꾸는가 | 신호 문항 지시 길이 | 두 문항 JSON의 UTF-8 크기 |
|---|---|---:|---:|
| baseline | 현행 전문가 검토 지침을 포함하는 기준판 | 412자 | 7,358바이트 |
| short | 신호 문항의 추가 검토 문단만 제거한다. 기존 등급 설명을 보존한다. | 134자 | 6,667바이트 |
| verify | 독립 확인이 필요한 현재 요구를 묻고 직접 요구·확인 방해·일상·불명확 기준을 네 색에 대응시킨다. | 97자 | 6,474바이트 |

두 문항 JSON의 크기는 Python 기본 구분자, ensure_ascii=False로 계산했다. 토큰 수와 지연은 별도로 측정한다. 행동 문항의 수신자 관점과 20개 선택지, 원점수, 표시 보정, 화면 응답 계약은 세 설정이 공유한다. verify와 baseline 사이에는 지시 길이와 내용, 등급 설명이 모두 달라지므로 결과 차이를 길이 하나에 귀속할 수 없다.

## 팀 Zoro에서 재현

Arena에서 정상 동작하는 로컬 Zoro 환경변수를 그대로 사용한다. 새 실행 디렉터리가 필요하다. 저장된 출력에는 원문이 들어가지 않지만 행 번호와 해시는 공개 데이터에 대응하므로 팀 실험 기록으로 관리한다.

```bash
git -c core.autocrlf=false clone https://github.com/ku-autoai/MessengerPhishingDetection.git corpus
git -C corpus -c core.autocrlf=false checkout 438cfbb251410fee791f49d75d928520847030c3
python -m tools.zoro.benchmark_signal --data-dir corpus/messenger_phishing_dataset/kor --out runs/signal-paired-01
```

이미 해당 원본 CSV가 있다면 마지막 명령에서 경로만 지정한다. 도구는 모델 호출 전 valid와 test의 원본 바이트 SHA-256을 검사한다. 테스트와 검증 라벨은 채점에만 쓰고 모델 요청에는 두 질문과 원문만 포함한다. 입력마다 세 설정의 실행 순서를 순환한다. 같은 서버 설정·체크포인트·head·온도를 끝까지 유지하고 실행 전후 모델 서버 정보를 별도로 함께 보관한다. 이 도구 자체가 모델 신원을 증명하지는 않는다.

- **manifest.json**에는 질문·입력 지문과 실행 상태가 들어간다. **predictions.jsonl**에는 행·설정별 원점수와 표시 결과, 표시 보정 이유, 시간, 해시가 기록된다.
- **summary.json**의 display는 시연과 같은 경보 기준이다. paired_vs_baseline은 새로 잡은 피싱과 새로 놓친 피싱, 사라진 정상 오탐과 추가된 정상 오탐을 구분한다. 피싱 초록률, 회색률, 정밀도, p50/p95도 확인한다. 실패하면 불완전 상태를 남기고 해당 실행을 최종 측정에서 제외한다.
- **score_replay_only**는 다른 실험이다. valid에서 빨강+주황 합산 점수의 임계값을 선택한다. 정상 오탐률 5% 이하에서 탐지 건수를 최대화하고 동률이면 오탐 건수가 적은 것을 고른다. 해당 값을 test와 반례에 적용해 TP·FP를 센다. 5%는 실험 설정이며 실제 화면의 색을 바꾸지 않는다.
- valid 275건, test 551건, 정상·예방과 직접 위험 요청을 포함하는 자체 개발 반례 20건을 각각 보고한다. 전체는 2,538회 호출이다. 합성 반례는 공개 사건 라벨과 평가 목적이 다르다. 이미 본 551건과 자체 개발 반례에서 좋은 후보도 새 사건군·정상 메시지로 잠금 평가를 거쳐야 한다.

후보 시연은 `python -m arena.server --signal-profile verify`로 실행한다. 옵션을 생략하면 baseline이다. 서비스 API 요청에서 사용자가 프로필을 덮어쓸 수 없다.

## 이번 실행에서 확인한 것

- 통제 HTTP 응답과 실제 로컬 전송 코드로 2,538회 요청·행 결합·채점을 완료했다. 이는 실행 경로 검증이다.
- Python 431개 중 기본 실행 429개 통과, 데이터 경로가 필요한 선택 시험 2개도 별도 실행하여 통과했다. Node 143개가 통과했다. 기존 질문 지문과 형식 검증, 동률·임계값·행 불일치·중단 시 처리 및 후보의 HTTP 진입점을 시험했다.
- 이번 환경에서는 모델이 구성되지 않았으며 실제 벤치마크 명령은 MODEL_NOT_CONFIGURED로 종료됐다. 따라서 공개된 기준판 17/50 탐지, 46/501 정상 오탐 이외에 short·verify의 신규 모델 성능값은 없다. 화면에 표시되는 551건은 저장된 기준판 결과다.
- 승격 여부는 실측된 누락·오탐의 변화, 피싱에 뜨는 초록과 지연을 함께 보고 결정한다. 예시 목표는 독립 표본에서 탐지율 +10%p, 정상 오탐률 및 피싱 초록률 비증가다. 후보가 악화되면 baseline으로 실행한다. 코드 전체 복구는 이 통합 PR의 별도 revert로 가능하다.
