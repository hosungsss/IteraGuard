# v5.9 · 대화형 사고 대응 가이드 (Guided Incident Conversation)

2026-11-19 KST · 작업 범위: Zoro 판단 후 대화형 UI + 후속 사고 대응. **실제 무제한 생성형 챗봇이 아니라, 기존 판단에 연결된 제한적 질문·상황별 가이드**입니다. 작성 시점의 기준 main: `cca6767d9a5f9751e8785bd2179ac357ee52febf`.

## 제품적 결정

사용자가 제시한 화면의 장점은 문자 판단으로 끝나지 않고 '링크만 눌러도 되나?' → '이미 눌렀다' → '앱을 설치했나/인증번호를 입력했나/송금했나'로 상황이 변할 때 다음 단계가 이어진다는 점입니다. 반례는 '나중의 무해한 질문'을 현재 사기 문자로 다시 분류해 이전 강한 위험을 잘못 해제하는 경우입니다.

이에 따라 **원문 문자 판단은 기존 /api/evaluate에만** 맡깁니다. 후속 질문은 **별도 /api/conversation/followup**에서 최근 실제 저장 EVALUATE 이벤트와 동일 세션·버전·OPEN 상태를 확인한 뒤, 규칙 기반의 보수적 안내를 반환합니다. SQLite 저장·업무 생성·상태 수정·모델 추가 호출·Jev 과금이 전혀 없습니다.

## 구체적인 사용자 흐름

1. **새 합성 문자 입력** → 기존 Zoro typed model / 독립 정책 / Session Task 처리. 모델 장애 시 그 장애를 표시합니다. 임의 답변은 생성하지 않습니다.
2. **화면에 첫 대화 쌍 추가** → 사용자 원문(브라우저 일시 메모리) + 서버가 실제 승인한 판정·Task 수·출처·위험 유지 상태. 서버 DB에는 기존과 같이 원문 transcript가 없습니다.
3. **후속 질문 선택** → 링크만? 이미 클릭? 파일 다운로드? 앱 설치? 정보 입력? 송금? 공식 확인? 등. 자연어 입력은 보수적으로 매핑 가능한 제한된 구문만 인식하고, 알 수 없으면 선택지를 요구합니다.
4. **서버 읽기 전용 확인** → 세션 id, version, synthetic_only, scenario만 POST. 서버는 가장 최근 이벤트가 EVALUATE여야 하며 상태가 OPEN/버전 일치인지 검증합니다. 후속 질문 원문은 전송하지 않습니다.
5. **대화형 대응 안내 표시** → 현재 상황의 안전한 원칙과 공식 기관 URL만 표시. '규칙 기반 안내, Zoro 재추론/생성형 GPT 아님'을 명시합니다.
6. **새 원본 문자 변경/새 세션/실패** → 이전 응답을 현재 판단으로 재사용하지 않습니다. 세션 전환 시 브라우저 메모리의 채팅 내역을 삭제합니다. 원본 문장 수정 시 기존 대화는 참고용으로 표시되지만 새 후속 요청을 차단합니다.

KISA는 '링크 클릭'과 '앱 설치/실행'을 구별할 필요가 있다고 안내합니다. **클릭만으로 감염을 단정하지 않는 것은 안전 보증과 다릅니다.** 앱 설치, 로그인 정보 입력, 실제 송금이 확인되면 각각 다른 대응을 안내합니다. 국내 상담 118(스미싱), 금전 피해 경찰 112 및 해당 금융기관 공식 채널을 사용하되, 사용자의 국가를 임의 추정하여 실제 신고·연락하지 않습니다.

## SNM · 위험·실패 경로

- **정상:** 유효한 첫 판단 → 링크 클릭 가정 → 실제 클릭 → 추가 설치/인증정보 여부 → 공식 확인.
- **적대 입력:** 프롬프트 인젝션처럼 보이는 텍스트를 넣어도 서버는 질문 원문을 받지 않으며 scenario allowlist만 수용합니다. DB/코드 실행 없음.
- **혼합 문장:** 예를 들어 '링크 클릭 + OTP 입력'은 더 큰 위험에 해당하는 명시적 유형을 우선 안내하나, 전체 상황을 진단한 것으로 오인해서는 안 됩니다.
- **모호함:** '이거 괜찮아요?' 같은 불명확한 질문에는 생성형 모델의 임의 응답을 출력하지 않고 분기 선택을 요구합니다.
- **모델 장애:** 후속 안내는 일반 사고 대응 정보라는 출처가 표시되며 원본 모델의 신뢰성이 복구된 것처럼 표시하지 않습니다.
- **중복·지연·역순:** 한 화면에서 이중 호출을 차단하고, 버전 검사와 응답 바인딩을 수행합니다. 버전이 변경되면 새로 판단해야 합니다. 후속 API에는 DB write가 없습니다.
- **개인정보:** 채팅 원문은 브라우저 메모리만 사용하고 localStorage·SQLite·Jev로 전송하지 않습니다. 원본 SMS 평가의 별도 데이터 계약은 그대로 유지됩니다.
- **복구:** 오류 발생 시 잘못된 성공 답변을 만들지 않고 이전 위험이 남았음을 알립니다. refresh 및 재판단을 안내합니다.

## 4D Ontology

- **구조:** 원본 문자 → Zoro typed proposal → 독립 정책 → 판정/Task → 선택된 후속 상황 → 일반 대응 안내. 후속 상황은 모델 판정이 아닙니다.
- **시간:** 원본 판단 버전과 후속 안내 버전의 일치를 요구. 세션 전환·close/reopen·새 판단으로 이전 응답을 현재로 승격하지 않습니다.
- **관점:** 수신자(행동 안내), 피해자(추가 피해 최소화), 기관(공식 확인), 정상 발신자(오탐 방지), 심사위원(모델 기여의 출처 구분).
- **역검증:** 각 후속 안내에서 scenario ID, 세션 버전, 규칙 기반 모드, 공식 출처로 재확인할 수 있습니다. Zoro 원문/가중치 신원이나 제삼자 신고를 검증했다고 주장하지 않습니다.

## 남은 한계 및 안전한 다음 과제

**개발·검증은 정확한 CI 커밋에 따라 확인해야 합니다.** 이 코드는 안전하고 유용한 9개 상황형 follow-up을 목표로 하며, 자연어 임의 질문에 대한 범용 GPT 수준 상담을 구현하거나 보장하지 않습니다. 사용자가 후속 질문으로 새로 밝힌 사실이 기존 SQL Task에 자동 등록되지 않습니다. 별도 승인 후 개인정보 처리·관찰 증거 provenance가 정리되면 독립적인 사고 입력 기록과 상담 이력 보존을 설계할 수 있습니다.

실제 Zoro 추론, 실브라우저 화면·키보드/스크린리더 점검, 긴급사고 신고, 실제 문자 통합, 외부 생성형 AI 연동 및 독립 상담 정확도 평가는 NOT_RUN입니다. 기존 v5.9 라이브러리 없는 3D 그래픽·패키지 버전/가중치·Jev Shadow·Rulebook은 유지합니다. 변경 취소는 이 PR을 revert하면 되며 DB migration은 없습니다.
